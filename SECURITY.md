# Security Policy

The Code Academy team takes the security and privacy of its users seriously.

## Supported versions

Security fixes are generally prioritised for the version currently deployed and actively maintained by the Code Academy team. Include the version or deployment details in your report if known.

## Reporting a vulnerability

**Do not disclose suspected vulnerabilities in public GitHub issues, pull requests, social media posts, or community chats.**

Report vulnerabilities privately:

1. If GitHub private vulnerability reporting is enabled, use the repository's **Security → Advisories → Report a vulnerability** option.
2. Otherwise, contact the maintainers through an official private contact channel published by Code Academy.

**Before publishing this file:** enable GitHub private vulnerability reporting or add and test an official security-reporting email address. Do not invent a contact address.

## What to include

- A description of the suspected vulnerability.
- The affected page, feature, endpoint, or component.
- Steps to reproduce it.
- Potential impact.
- A proof of concept, logs, or screenshots, with secrets and personal data removed.
- Suggested mitigation, if known.

Do not access, modify, download, or disclose another person's data while investigating. Avoid destructive tests or anything that could disrupt the service.

## Response

Maintainers will review the report, may request more information, and will work to verify and address confirmed issues. Please allow reasonable time for investigation and remediation before public disclosure.

## Responsible testing

Only test systems you own or have explicit permission to assess. Do not attempt to access another user's account or private information, bypass access controls, misuse access codes, disrupt the platform, or publish credentials and personal information.

Thank you for helping keep Code Academy and its users safe.
